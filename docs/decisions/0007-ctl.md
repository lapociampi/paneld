## Context

Writing and debugging configs needs a quick loop, and local scripts need a simple way to talk to the running program (inspired by `hyprctl`).

## Decision

The same binary is also the client: `paneld ctl <command>` talks to the running program over a Unix socket, in v1. `paneld check` validates a config without a running program.

| Command | Does |
| --- | --- |
| `reload`, `check` | Reload or check the config |
| `eval '<cel>'` | Evaluate an expression against the current values |
| `set vars.x=<value>`, `goto <page>` | Drive the UI |
| `theme [<name> \| --reset]` | Show or switch the active theme until reset or restart ([Themes](../themes.md)) |
| `alert fire\|resolve <id> ...` | Raise or resolve an alert from a local script |
| `status` | Sources (last value, age, errors), active alerts, config file list |

## Consequences

- Socket permissions decide who may control the panel (owner and group only).
- An inbound, generic interface: it names no service, so [ADR 0005](0005-commands-only.md) still holds.
- No network listener: remote control stays out of v1.
